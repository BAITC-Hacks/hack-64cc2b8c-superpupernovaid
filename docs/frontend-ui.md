# Интерфейс Qoryt

По умолчанию интерфейс использует backend. «Посмотреть демо» включает прежние
демонстрационные экраны; «Подключить API» возвращает реальные данные. Загрузка
новой записи всегда создаёт настоящее совещание. Ошибки запросов показываются
с кнопкой повтора, без автоматической подмены данными демо.

## Подключённые сценарии

- Обзор: все страницы GET /meetings и GET /tasks, реальные счётчики и ближайшие сроки.
- Выбор карточки и завершение загрузки открывают workspace соответствующего ID.
- Workspace: GET /meetings/{id}/result, /processing и /processing-run каждые 2 секунды.
  Polling останавливается при completed/failed; повтор запуска возобновляет обновления.
- После загрузки POST /meetings/{id}/process запускает полный фоновый цикл.
  В workspace можно запустить обработку старой записи или повторить неудачную попытку.
  «Только транскрипт» сохраняет отдельный путь preprocess → speech без ИИ-анализа;
  он блокируется во время активного фонового запуска.
- PDF/DOCX скачиваются через GET /meetings/{id}/exports/{format}; ошибки 409/429
  показаны пользователю, HTTP-клиент проверяет MIME и сохраняет бинарный файл.
- Транскрипт: загрузка всех cursor-страниц и объединение соседних сегментов одного
  speaker_id в цельные реплики с таймкодом начала. Поиск локальный по полным репликам,
  включая фразы на границах исходных сегментов. «Обновить» перечитывает транскрипт.
  При конфликте версии кнопка повтора начинает чтение с первой страницы.
- Участники: PATCH /meetings/{id}/participants/{speaker_id} сохраняет имя.
- Поручения: чтение всех страниц, локальные поиск/фильтры, PATCH /tasks/{id}
  сохраняет статус. POST /meetings/{id}/tasks создаёт поручение с исполнителем и сроком.
- Обзор и общая доска поручений обновляются каждые 15 секунд.

Саммари и решения показываются из ответа backend. Экспорт доступен после сохранения
анализа и завершения активной обработки. Полный цикл требует настройки speech,
canonicalization и intelligence на сервере; ошибки конфигурации не подменяются демо.
Демо-экспорт старого интерфейса остаётся только в явно выбранном демо-режиме.

## Запуск

`docker compose up -d --build backend worker frontend` — приложение на http://localhost:8080.
Compose применяет миграции перед запуском backend. Для dev используйте существующий
compose.dev.yaml: Vite проксирует /api на API_PROXY_TARGET (по умолчанию localhost:8000).
Production nginx обновляет адрес backend через Docker DNS, поэтому пересоздание
контейнера backend не требует отдельного перезапуска frontend.

По умолчанию HTTP-клиент обращается к /api/v1 на текущем origin. Для отдельного API
задайте VITE_API_BASE_URL, например http://localhost:8000/api/v1, при сборке Vite.
Backend должен разрешать origin фронтенда в CORS. Секреты в VITE_* не помещайте.

## Код

- features/meetings/LiveDashboard.tsx — реальный обзор.
- features/meetings/LiveWorkspace.tsx — результат, этапы, участники и транскрипт.
- features/meetings/liveApi.ts — DTO и вызовы meetings/tasks/speech.
- features/tasks/LiveTasks.tsx — список, фильтры, создание и смена статуса.
- lib/useRemote.tsx — загрузка, повтор, polling и игнорирование устаревших ответов.
- Dashboard.tsx, MeetingWorkspace.tsx, TaskBoard.tsx, data.ts — демонстрационные экраны.

Навигация хранится в hash URL: `#/meeting/{uuid}`, `#/tasks`, `#/notifications`.
Перезагрузка, прямые ссылки и кнопки назад/вперёд сохраняют выбранное совещание.
Демо явно обозначено параметром `?demo=1`; реальные записи всегда открываются через API.

История протоколов загружает `/protocol-versions` с offset-пагинацией и скачивает
PDF/DOCX конкретной неизменяемой версии. Старые версии доступны даже при ошибке
новой обработки. В карточке совещания можно менять текст поручения, исполнителя и
точный срок в местном времени; API получает ISO-дату с часовым поясом.

Колокольчик открывает уведомления: непрочитанные, прочитанные и все, постранично.
«Проверить сроки» запускает внутренний scan; «Прочитано» сохраняет статус на сервере.
Для автоматического scan раз в 5 минут: `docker compose --profile reminders up -d reminders`.
Письма не отправляются. Поиск совещаний фильтрует реальные названия.

Авторизация и роли остаются отдельным этапом. Обработка требует работающий Celery worker.
