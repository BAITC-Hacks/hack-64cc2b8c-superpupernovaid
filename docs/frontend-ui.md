# Интерфейс Qoryt

Фронтенд покрывает основной пользовательский сценарий системы автопротоколирования:

1. секретарь открывает обзор совещаний и поручений;
2. создаёт совещание и загружает аудио или видео;
3. файл передаётся в существующий Media API и запускается подготовка аудио;
4. после обработки пользователь работает с саммари, решениями, транскриптом и поручениями;
5. поручения контролируются на отдельном экране по срокам и статусам.

## Структура

```text
frontend/src/
  components/
    layout/AppShell.tsx       # desktop/mobile навигация и общий каркас
    ui/Icon.tsx               # единый набор интерфейсных иконок
  features/
    meetings/
      api.ts                  # типизированные вызовы upload/preprocess
      data.ts                 # демонстрационные данные до появления meeting API
      Dashboard.tsx           # обзор и последние совещания
      NewMeeting.tsx          # загрузка записи и параметры обработки
      MeetingWorkspace.tsx    # саммари, транскрипт, поручения, экспорт
    tasks/
      TaskBoard.tsx           # фильтры и контроль исполнения
    jobs/                     # прежний demo agent scaffold, не используется Qoryt UI
  lib/http.ts                 # общая HTTP-обвязка
  App.tsx                     # переключение продуктовых экранов
  style.css                   # дизайн-система и responsive breakpoints
```

## Реальные и демонстрационные данные

- Загрузка файла подключена к `POST /api/v1/meetings/{meeting_id}/media`.
- Подготовка аудио подключена к `POST /api/v1/meetings/{meeting_id}/media/{media_id}/preprocess`.
- Список встреч, транскрипт, саммари и поручения пока используют явно локальные демонстрационные данные из `features/meetings/data.ts`, их нужно подключить к новым API meetings/tasks/result/transcript (см. backend-ui-contract.md).
- Кнопка экспорта создаёт текстовый черновик. После появления Protocol API её нужно заменить на получение PDF/DOCX с сервера.

## Точки следующего подключения

- заменить локальное переключение экранов на URL-маршруты после утверждения route contract;
- подключить meeting lifecycle и историю совещаний;
- добавить polling/SSE для стадий ASR, diarization, alignment и intelligence;
- получать `AttributedTranscript` и `StructuredMeetingResult` с backend;
- сохранять ручное сопоставление `speaker_id → participant`;
- подключить серверный PDF/DOCX export и рассылку выдержек;
- заменить локальное изменение статуса поручения на Task API;
- добавить авторизацию и роли до внешнего развёртывания.

Создание встречи, загрузка и preprocessing работают через backend. При отдельном запуске Speech backend использует NVIDIA Cloud; прежнее описание только локальной обработки больше не соответствует текущей конфигурации.

Форма NewMeeting теперь вызывает POST /meetings, передаёт метаданные и явное согласие. Остальные экраны пока демонстрационные.
