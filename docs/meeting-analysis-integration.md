# Интеграция агентного анализа

## Запуск

Применить миграции до `0008` (следует за `0007_protocol_exports`). В `.env` указать
`OPENAI_API_KEY`, пять `MEETING_*_MODEL` для extraction/resolver/summary/review/speaker_resolution,
затем `MEETING_INTELLIGENCE_ENABLED=true`. Реальные ключи и модели в патч не включены.
AI_MODE не переключает этот модуль на mock: отключённый модуль возвращает 503.

После создания встречи, загрузки, preprocess, speech и canonicalize вызвать
`POST /api/v1/meetings/{meeting_id}/analyze` без тела. Ответ 200 имеет ту же схему,
что GET `/result`. Внешние поля transcript/evidence — строковые UUID, как требует
фронтенд. Внутренние Speech и CanonicalTranscript остаются неизменными.

409: отсутствует актуальная канонизация/транскрипция либо контекст изменился во время LLM.
429: ёмкость анализа занята. 502: невалидный ответ агента. 503: модуль отключён,
провайдер или хранилище недоступны. Никакой частичный результат в UI не публикуется.
Повторный вызов для опубликованной версии возвращает результат без повторной генерации
и дублирования поручений. Смена модели сама по себе не перезаписывает опубликованную
версию и ручные исправления.

Для общего pipeline: `from app.intelligence.dependencies import analyze_meeting`;
`await analyze_meeting(meeting_id)` использует тот же coordinator. При отдельном
`asyncio.run()` на задачу worker вызывать `await shutdown_analysis()` в finally до
закрытия event loop; SDK-клиент не следует переносить между разными event loops.
Создание очереди/worker не входит в этот патч.

## Контракт и границы

`analysis_details` — nullable дополнительное поле ResultView с полным типизированным
результатом, review_required/issues, unresolved_questions и speaker_mapping.
ID `analysis_details.action_items[].id` совпадает с опубликованным `tasks[].id`.
Детали являются снимком анализа; текущие ручные изменения задач читаются из `tasks`.

Источником подтверждённых имён служат именованные участники текущей транскрипции.
Ручные имена передаются как overrides и не заменяются моделью. Если имён нет,
спикеры остаются неразрешёнными; имена не выдумываются. Отдельный реестр приглашённых
участников пока не добавлен.

`scheduled_at` не подменяет фактическое начало записи. Пока нет подтверждённой даты
и IANA timezone, относительные сроки остаются неразрешёнными и требуют проверки.
Агент возвращает дату, а UI `due_at` требует timestamp: дата и исходная формулировка
сохраняются в `analysis_details.action_items`, `due_at` остаётся null до ручного
уточнения времени/зоны. Никакой неоговорённой полуночи UTC.

`meeting_tasks.origin` отделяет ручные задачи от сгенерированных. Миграция распознаёт
исторические ручные задачи по `task.create` в аудите, а также по отсутствию transcript_id.
Остальные привязанные задачи считает generated. Старые AI-задачи не удаляются;
в result, task lists и export видны только актуальные плюс все ручные задачи.
Старые evidence ручных задач остаются в БД, но в текущей проекции возвращается пустой
список: нельзя направлять пользователя к другой реплике новой версии.

Экспорт проверяет уникальность ID и существование каждой evidence-ссылки. Невалидный
протокол отклоняется до рендеринга. Нужен новый export hash; старые файлы не переписываются.

Агентный runtime использует Agent/output_type и Runner SDK, ограниченные чанки,
параллелизм, бюджеты, повторные попытки transient ошибок и проверку evidence.
Документация SDK: https://developers.openai.com/api/docs/guides/agents/define-agents
