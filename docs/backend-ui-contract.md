# Backend для Qoryt UI

Исходное описание фронтенда сохранено в `frontend-backend-contract.md`. Оно описывает
целевой продукт; актуально реализованные возможности и отличия перечислены здесь.

## Границы модулей

- `meetings`: сущность совещания, неизменяемая история согласия на запись, участники,
  ручные имена, проекция результата Speech, чтение прогресса и аудит изменений.
- `media` и `audio`: исходный файл и нормализованное аудио. MediaAsset теперь имеет FK
  на Meeting; NormalizedAudio связан с ним через MediaAsset.
- `speech`: существующие адаптеры и хранилище оригинального транскрипта. Участники
  создаются в одной транзакции с транскриптом, без побочных действий в GET.
- `intelligence`: модели summary/decisions и атомарная публикация результата агентного
  анализатора. Решения и сгенерированные поручения требуют валидные ссылки на сегменты.
  Агенты запускаются после канонизации; см. `meeting-analysis-integration.md`.
- `tasks`: ручное создание поручений, назначение, сроки, приоритеты, фильтры и аудит.
- `protocols`: детерминированный DOCX/PDF экспорт готового протокола; [контракт и примеры](protocol-export.md).
- `notifications`: выделена граница модуля, отправка уведомлений не запускается.

## Реализованные маршруты

| Метод | Маршрут | Поведение |
|---|---|---|
| POST | `/api/v1/meetings` | Создаёт встречу и отдельную запись согласия |
| GET | `/api/v1/meetings` | Список новых сначала; cursor/limit/status |
| GET/PATCH | `/api/v1/meetings/{id}` | Чтение и разрешённые изменения метаданных |
| GET | `/api/v1/meetings/{id}/processing` | Состояние последней загруженной записи и шагов |
| GET | `/api/v1/meetings/{id}/result` | Метаданные, участники, nullable summary, решения, поручения |
| GET | `/api/v1/meetings/{id}/transcript` | cursor/limit/q; миллисекунды, UUID, без выдуманных confidence/language |
| PATCH | `/api/v1/meetings/{id}/participants/{speaker_id}` | Ручное имя участника текущей версии транскрипта |
| GET/POST | `/api/v1/meetings/{id}/tasks` | Список/ручное создание поручения |
| GET | `/api/v1/tasks` | status/assignee_id/due_before/q/cursor/limit |
| PATCH | `/api/v1/tasks/{id}` | text/status/assignee_id/due_at/priority |
| POST | `/api/v1/meetings/{id}/analyze` | 200: ResultView; 409: нет текущей канонизации; 503: отключён/не настроен |
| POST | `/api/v1/meetings/{id}/exports` | 200: ExportedDocument, JSON `{ "format": "docx" }` или `pdf`; 409: анализ ещё не сохранён |
| GET | `/api/v1/meetings/{id}/exports/{format}` | 200: DOCX/PDF attachment; 409: анализ ещё не сохранён |

Все схемы доступны в Swagger `/docs`. PATCH включён в CORS. Неизвестные поля изменения
отклоняются. Время scheduled_at/due_at принимается с часовым поясом. Nullable поля можно
очистить через null, но title/text/status/priority нельзя очистить таким образом.

## Семантика

`draft` — дополнительный статус до первого файла. Для остальных стадий используйте
`processing.steps[].status`: pending/running/completed/failed. Стадия верхнего уровня
может ожидать запуска: например analyzing с pending не означает, что LLM уже работает.
Поле progress равно 100 только для завершённого шага; иначе null, а не искусственный
процент. Шаги сохраняются из фактического процесса и переживают отключение HTTP-клиента.
Это пока не надёжная очередь: после аварийного завершения процесса running может
сохраниться до повторного запуска. Polling поддержан; SSE и восстановление задач не добавлены.

`ready` появляется после публикации analysis, а не после одного ASR. Пока analysis
нет, summary=null, decisions/tasks пусты (за исключением вручную созданных поручений).
Экспорт требует опубликованный анализ. Analyze возвращает 503, если агенты отключены.

ResultView дополнен nullable `analysis_details`: проверка качества, исходные сроки,
сопоставления спикеров и полный сохранённый агентный результат. Остальные поля сохранены.
Списки задач и экспорт показывают ручные задачи плюс AI-задачи актуальной транскрипции.
Ссылки ручных задач на старую версию остаются в БД, но не выдаются как ссылки на текущий текст.

Активная запись — последняя по created_at/id; активный транскрипт — последний
сохранённый Speech-артефакт этой записи. Старые версии не удаляются. Переименование
speaker_id относится к конкретной версии; имена не переносятся между разными запусками
диаризации автоматически. Assignee имеет отдельный UUID. При назначении проверяется
принадлежность совещанию. UNKNOWN не считается идентифицированным участником.

Исторические ID `seg_<uuidhex>` преобразуются в UUID в транспортной схеме. Исходный
Speech/Canonicalization payload остаётся неизменным. Решения и поручения используют
UUID из нового `/transcript`. Cursor транскрипта привязан к версии и поисковой строке;
при их изменении — 409, начать чтение заново. Внутри используется существующий JSON
Speech-артефакт; SQL-индексирование каждого сегмента — следующий шаг для больших объёмов.

speech_share — доля суммы длительностей атрибутированных текстовых сегментов, а не
точная доля голосовой активности. started_at, confidence, language остаются null,
language_detected=[]: текущие артефакты не содержат достоверных данных для этих полей.

`overdue` вычисляется по due_at и текущему UTC времени; завершённое поручение остаётся
completed. PATCH overdue допустим только с прошедшим сроком. PATCH in_progress при
прошедшем due_at по-прежнему отображается как overdue; для снятия просрочки измените срок.
Ручное поручение может не иметь ссылок на транскрипт; сгенерированное обязано иметь их.

## Миграция и запуск

`make migrate` применяет 0006 без пересборки. Старые meeting_id из MediaAsset получают
строки Meeting с сохранением UUID и исходных артефактов. Для них consent неизвестен
(история `legacy_unknown`, публичное поле null), а не подтверждён задним числом.
Новая загрузка требует существующее совещание и подтверждение согласия (404/409).
Метаданные согласия не меняются через общий PATCH; API изменения согласия пока отсутствует.

NewMeeting теперь создаёт встречу на backend и передаёт фактические значения формы;
согласие по умолчанию снято. При повторе после ошибки подготовки переиспользуются
созданные meeting/media ID. Таймаут загрузки/подготовки увеличен отдельно от обычных GET.
Остальные экраны пока используют demo-данные; API для их подключения готов, но полная
интеграция Dashboard/Workspace/TaskBoard не входит в это изменение.

## Текущие ограничения

По принятому решению используется NVIDIA Cloud, а не локальный RU/KZ ASR из исходного
документа. Сохранены известные ограничения провайдера (русский, четыре speaker slots,
16 МиБ WAV). expected_participant_count и language_hint — метаданные, они не снимают
эти ограничения. Подписи формы приведены в соответствие облачному режиму.

Авторизация, роли, проверенная личность автора аудита, защищённое скачивание и
уведомления ещё не реализованы. Аудит сохраняет факт/поля изменения, но не подтверждает
личность оператора. API предназначен для существующего локального прототипа;
доступ по ролям из исходного документа остаётся отдельным этапом.
